# Prompt dev — Itération N · Phase 2.1 : bascule Doux/Anguleux = no-op sur la canonical

**Type** : `fix(iter-N/phase-2.1)`. Petit correctif isolé, sans risque.

## Bug

`SET_SPLINE_INTERPOLATION` (`src/reducer.js`, ~l.1930) recompose la canonical
depuis le résidu **gelé** :
```js
canonical: splinePlusResidual(splineToPoints(anchors, NOUVEAU_mode), residual_gelé)
```
Or `residual` avait été calculé contre l'**ancien** mode. Le switch ajoute donc
`[spline(anchors, nouveau) − spline(anchors, ancien)]` à la canonical → **le
tracé se déforme alors qu'on n'a bougé aucune ancre**. Surprenant et indésirable.

## Fix

Au switch, **garder la canonical strictement identique** et **recalculer le
résidu contre le nouveau mode** :
```js
case 'SET_SPLINE_INTERPOLATION': {
  const interpolation = action.payload === 'hard' ? 'hard' : 'soft'
  if (state.editor.interpolation === interpolation) return state
  const residual = computeResidual(
    state.editor.canonical,
    splineToPoints(state.editor.anchors, interpolation),
  )
  return {
    ...state,
    editor: { ...state.editor, interpolation, residual },
  }
}
```
- `canonical` **inchangée** → le switch ne change que *comment un futur drag
  d'ancre déformera* (et la courbe orange « spline des ancres », qui est la
  tendance, change de forme — c'est normal et voulu).
- **Ne plus forcer `canonicalNormalized: false`** : la canonical ne bouge pas,
  donc son statut de normalisation est préservé (on le laisse tel quel).
